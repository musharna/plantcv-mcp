# Pre-registration: confirmatory re-run, 2026-10-18

Committed before the sweep. Anything run after the sweep is exploratory and
is labeled so.

**Why.** On 2026-10-17 the server arm was less accurate than Claude with Bash
(86.2% vs 95.7% of answers; questions right in every run 37 vs 42, exact
McNemar p = 0.18). This branch adds what the misses pointed to: `segment`
rules with OR/AND combine (yellowed-leaf areas), `zoom_image` (leaf counts by
eye), a seeded split in `count_leaves`, and `traits=` on `measure` and
`measure_regions`.

**Server under test.** `git+https://github.com/musharna/plantcv-mcp@051aff0544d4fa7337a8a891619c70c1bf90dd96`
is unreleased and still reports version 1.16.1. Its dependencies are pinned
with `--exclude-newer 2026-10-17`, plus PlantCV 4.11.3 and opencv-python
4.11.0.86. `run.py` checks that NumPy (2.4.6) and scikit-image (0.26.0) match
the alt arm's before the sweep starts.

**Arms.** Both arms are re-run with the 10-17 prompt, isolation and tools:

- `alt`: Claude + Bash/PlantCV/OpenCV + web.
- `mcp`: Claude + this server + Read.

The arms are interleaved by question: for each rep, each question runs alt and
then mcp. The bare arm is not re-run. The model is claude-opus-5-5 in
Claude Code, with `--workers 1`.

**Questions, reps, scorer.** The 46 questions in `questions.json` are
unchanged, and their images are checked by sha256. Each question runs 3 reps
per arm, so 276 runs in total. The scorer is `score.py` and the validity rule
is `run.py assess()`, both unchanged. Invalid runs are kept and never retried.

**Primary endpoint.** The primary endpoint is the number of questions right in
every valid rep, with at least one valid rep, paired over questions. This is
`stats_paired.tsv`, subset `all`.

**Win rule** (from the 10-18 decision ledger):

1. Non-inferior: mcp_all_right ≥ alt_all_right − 2.
2. Better: an exact two-sided McNemar test (binomial on the discordant
   questions) gives p < 0.05 in mcp's favor, AND the 95% percentile
   bootstrap CI of the paired difference excludes 0 (diff_lo > 0). The
   difference is the mcp minus alt share of questions right in every rep,
   over 4,000 resamples of questions, using plot.R's seed.

The result is reported in one of three ways:

- **Win**: both 1 and 2 hold.
- **Tie**: 1 holds but 2 does not.
- **Loss**: 1 fails, or McNemar p < 0.05 in alt's favor.

**Power, stated in advance.** On 10-17 the alt arm was right in every run on
41 to 42 of 46 questions. McNemar needs at least 6 discordant questions, all
for mcp, to reach p < 0.05 (6-0 gives p = 0.031; 5-0 gives p = 0.0625). So
mcp can only win if alt misses at least 6 questions that mcp gets right every
time. A tie is the expected best case.

**Secondary, descriptive (no rule).**

- Share right with bootstrap CIs, on all questions and on the 18 a color cut
  misses.
- Median cost and seconds per answer with CIs.
- The token breakdown per arm from `diagnose.py` (fixed context, tool output,
  turns, cache), compared with 10-17.
- Mechanism readout from `diagnose.py --mechanism`: how many valid mcp runs
  used rules, zoom_image, seeds or traits. A fix no run used was not tested.

**Controls, all active.**

- The oracle check runs before the sweep (`run.py`).
- The no-model baselines (`baselines.jsonl`) are reused unchanged.
- The validity rule applies, and the leak scan runs in every run.
- `run.py --audit` re-scans all transcripts after the sweep.
- The paired test and bootstrap CIs are computed as above.
