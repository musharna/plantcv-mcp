# Lessons

One line per miss: date, the class of miss, and the mechanism that now catches it.

- 2026-09-16: Input validation covered the shapes I imagined, not the shapes the boundary can receive (empty/truncated files, JSON of the wrong type, floats whose SQUARE leaves the range, ints past int32 reached native code before the geometry check). Caught now by: decoders wrapped at the loader (thermal, hyperspectral), a str check before dict membership (refine), a guard on the derived factor rather than the input (measurement), and the grid predicted in Python ints before any native call (regions); the weekly hypothesis fuzz job (nightly-guardrails.yml) is the mechanism that finds the next such shape. (#96)
- 2026-09-16: A leaked child process is a class the test runner cannot see, because its own exit hides it; the harness that runs the suite in-process (mutmut's stats pass) inherits the child and crashes when it dies. Now: `tests/conftest.py` shuts the worker down at session end and fails the session on any surviving spawn child, and the nightly gate treats a mutmut exit that is neither 0 nor the cap as an abort.
- 2026-09-18: A validated LOWER bound is half a range: `count_leaves(min_distance)` sized a padding ring and skimage's peak footprint from a client integer with no upper bound (200000 asked for 1.9 TB), and two docstrings quoted a different tray than the guide for what read as one measurement. Caught by PR review, not by a test. Now: the value is checked against the mask's own extent before anything is allocated, with a test that fails on the old code under a memory cap; figures quoted in code name the tray they came from. No hook can see "this integer sizes an array", so the standing mechanism is the weekly hypothesis fuzz job (nightly-guardrails.yml), which fuzzes public entry points and so now reaches count_leaves. (#111)
- 2026-09-22: Tests that call the impl functions cannot see what the tool boundary does to their result. The measure_images output schema was a hand-kept copy narrower than what batch.py returned, pydantic dropped the difference, and every batch test passed because none went through the tool. Caught by an external bug audit, not by CI. Now the result contract lives with its producer, every output TypedDict is closed (extra=forbid, so drift fails the call), and tests/test_tool_boundary.py drives a real in-process Client and checks that every structured tool publishes a closed schema.
- 2026-09-22: The 2026-09-18 lesson ("a lower bound is half a range") was fixed for one parameter, not for the class. Four more size/iteration integers (refine iterations and ksize, checkerboard corners, threshold ksize) still had only a floor, and fill_size did not even have that. Now every such range is stated in limits.py, and each entry point calls it. A ceiling is either the extent past which the value cannot change the result or a named practical limit. The same audit found two other half-checks: the decode gate checked channel count but not bit depth, and ranges skipped NaN but not Inf. Both are now handled at the single gate where the data enters.
